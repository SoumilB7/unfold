# Historical seed eligibility: capability 2

**No retained artifact in the requested scope is eligible for publication as a capability 2 cache seed.** This read-only audit covers all 106 files under `verification/s6/pilots`, `verification/s7/models`, and `verification/s7/observations`: 8 S6 pilot groups and 39 S7 groups, comprising 39 unique targets. All stored and decoded hashes are recorded. Inputs were not changed, imported into a cache, or regenerated.

- [Per-target findings](per-target.json) identify the actual request, inventory/summary, observation attempts, recipe hashes, provenance fields, and missing requirements for every group.
- [Artifact hashes](artifact-hashes.json) cover 19,486,600 stored bytes and 160,464,091 decoded bytes. There are no `identity` or `dependencies` cache envelopes in any of these artifacts.
- [Result and source pins](result.json) bind the review to the current capability 2 implementation and S7 writer. All scoped artifacts and contract sources remained byte-identical during the audit; the 39 referenced current S7 input files were also rechecked against their initially recorded hashes.
- [Actual SDXL request comparison](input-linkage-supplement.json) compares the old pilot request with the recorded schema 2 observation request. They differ in the requested factory module, label, timeout, primitive-capture flag, and 24 requested attribute lookups. No current request is guessed for the other targets.

The S6 pilots retain all eight successful inventory payloads, eight request files, and eleven explicit observation recipes/results. Nine observations succeeded; the DBRX text observation and Qwen2-VL vision-tower observation failed. Failed results are additionally excluded by the positive-only cache contract. Even successful results lack a completed capture-time capability manifest, actual worker search membership, consumed dependency/resource/package seals, full hashed effective environment, and worker/interpreter/isolation content identity. Their seven-axis provenance environments and source-file hashes remain historical evidence; they do not supply those missing fields. Optional false/empty request fields omitted by the existing wire format are not independently treated as defects.

Each S7 model artifact is a reconciliation summary with provenance, schedules, and a table, rather than a full `InventoryResult`. The 39 observation bundles retain 41 attempts: 22 successful and 19 failed, with 22 successful final outcomes and 17 failed final outcomes. Recipes and provenance are present, but no exact historical `BuildRequest` is embedded in these bundles, and no capability 2 capture envelope accompanies them. Eight targets have a possible S6 request companion; joining by config hash cannot recover the missing runtime and dependency capture. Current S7 input config hashes match the retained inventory provenance for all 39 targets. That comparison does not establish historical request flags or execution dependencies.

There is one additional format limitation: the S6 PixArt request and the S7 PixArt, Sana, and Nemotron inputs contain non-finite values. Their exact paths are recorded per target. Historical JSON/config hashing permits those values; current cache identity JSON refuses them. The audit preserves the historical hash convention for provenance comparison and separately records the current refusal. It does not replace infinity or rewrite inputs. [Audit correction](audit-correction.json) preserves the initial audit error and the corrected treatment.

This finding does not revoke S6/S7 evidence or recipes. They remain usable within their original historical scope and can specify a new real execution. A new supported capture may produce a valid cache entry; filling old artifacts with current environment values or fabricated capture manifests cannot. No model, observation worker, importer, cache publication, or latency measurement ran in this audit. The retained audit script is [audit.py.txt](audit.py.txt); its first version is preserved separately.
