# Pod A — Intent History: shipped product vs. the mechanisms built to reach it

Read-only research. Verified = I opened the file/line myself. Inferred = my synthesis across files.

## 1. The shipped product, in one paragraph

`model-unfolder` (PyPI `model-unfolder`, package `unfold-pkg/`) takes a Hugging Face model id, a
config dict, or an `AutoConfig` object and, without downloading weights, produces an interactive
self-contained HTML "web of pages" (entry page → block pages → op pages, to any depth) plus JSON,
cards, and parameter estimates — "turn any HuggingFace transformer into a clear architecture
diagram" (`unfold-pkg/model_unfolder/__init__.py:1`). The promise, stated by the project itself and
verified across eras: **"an honest, interactive architecture diagram — every block, arrow, repeat,
connector and split the model actually computes, drillable to the leaves, understandable by a
newcomer, and never fabricated"** (`z-docs/stale/PROJECT_CONTEXT.md:155-159`, quoted and reconciled
in `z-docs/10-full-research/00-goal-and-intent.md:33,38`). Current doctrine compresses this to:
**"a source-grounded architecture explainer. It supports a bounded, measured set of common
mechanisms and renders unresolved mechanisms honestly instead of guessing a familiar structure"**
(`z-docs/README.md:9-11`). Soumil's own words on who it is for and what "done" looks like
(`z-docs/10-full-research/16-owner-intent-and-open-questions.md:9-13,74-107`, verbatim 2026-09-02):
*"the single place any researcher, builder or worker goes to view the architecture of any model —
LLMs, diffusers, recursive models, anything"*; designs *"beautiful, valuable, intuitive"*; code
*"extremely modular, good quality, editable"*; and, critically, *"accuracy priority >>>>> code
length priority"* / *"things that aren't handled still render 100000% accurately"* — i.e. honesty
is not license for incompleteness; unhandled mechanisms take a small **beauty** hit, never an
accuracy hit, and templates must bend to the facts, never the reverse ("the whole venture is just
for accuracy i have absolutely no problem with beauty", same file l.84). The user is: researcher
reading a repo (first), learner (second), builder (third) — Soumil's answer to A1
(`16-owner-intent-and-open-questions.md:31,74`). This is the only place in the tree a user is
explicitly named; `00-goal-and-intent.md` documents that no prior doc ever wrote the user down
(§2, citing the audit twice).

## 4. Contradictions between docs

1. **Priority order, two versions, both claiming durable authority.** `00-start-here/project-doctrine.md:82-91` (chapter 00, "durable intent") ranks: (1) honesty/provenance, (2) ownership/mechanism, (3) cross-projection consistency, (4) preservation, (5) **completeness**, (6) visual polish. `10-full-research/00-goal-and-intent.md:175` issues a **restated priority order... "replacing `project-doctrine.md:82-91`"**: (1) no false claim, (2) **Tier-1 structure complete**, (3) Tier-2 mechanism, (4) canonical-fact consistency, (5) Tier-3 values, (6) learner's journey — moving completeness from 5th to 2nd. `z-docs/README.md:29-36`'s own "Document authority" section says chapter 09 (dated audits) "never overrides 07," implying chapter 10 (an even less authoritative research pass) should not override chapter 00 either — yet the entire post-Sep-2 execution plan (`12-execution-order.md`, `15-executor-brief.md`, every S-step since) runs on the restated three-tier order, not on the literal six-item doctrine text, and `project-doctrine.md` was never edited to match (verified: read in full, unchanged).

2. **Scope: SSM/Mamba/RWKV.** `unfold-pkg/README.md`'s "Supported model table" lists Jamba, Zamba, Mamba, Falcon-H1, RWKV (`00-goal-and-intent.md` promise 8, citing `README.md:85-98`), while `.claude/PROTOCOL.md:438` states *"Scope: LLMs and diffusion only (no SSM/Mamba)"* and the catalogue `toserve.md:14-15` states *"Out of scope: pure SSM/Mamba and RWKV token mixers."* The typing vocabulary (`everchanging/transformer/typing.yaml:55-57`) still names `ssm`/`recurrent`/`rwkv` mixers. Whether these render anything today is explicitly flagged **[unverified]** by the Sep-2 researcher and I did not re-verify it myself.

3. **Who is "owner."** Project doctrine and memory (`MEMORY.md` line 1: *"Claude is project OWNER"*) and `10-full-research/16-owner-intent-and-open-questions.md`'s opening line — *"Soumil handed ownership of the project to the reviewer (Claude)"* (2026-09-02) — together mean the human founder (Soumil) has delegated the role that decides what "done" means to a Claude session, which then authors its own audits (`FULL-AUDIT-2026-09-13.md`, byline *"owner: Claude"*), issues its own rulings (R1-R7), and grades its own prior work (`09-judgment.md §5`: self-issued grade **C+**, "project against its goal"). This is in tension with `NEW_AGENT_BRIEF.md:20-22`'s framing that Soumil is "owner of intent" and the reviewer is only "owner of coherence" — the actual documented delegation goes further than "coherence."

4. **The honesty claim itself was re-broken and re-fixed at least three times.** `00-goal-and-intent.md` promise 12 (2026-09-02) scores "never fabricated" as **kept**, citing "one wrong proven fact" total across 42 models. `FULL-AUDIT-2026-09-13.md` F-5 then finds DeepSeek-V3's canonical MLA width **confidently wrong** again (a *different* wrong number than the one already known from the shipped `17c` study). `FINAL-AUDIT-INDEPENDENT-2026-09-13` (a second, independent reviewer) then finds the **first** 2026-09-13 auditor's own reproduction claims wrong on ~9 separate points (`FINAL-PLAN-2026-09-14.md §1`). Each "the honesty bar holds" verdict has been falsified by the next, more rigorous look.

5. **Version/example staleness has been fixed since the last full audit, but silently.** The 2026-09-02 audit recorded a three-way version mismatch (pyproject 0.2.17 / `__init__.py` 0.2.15 / tags) and pre-campaign (May/June) examples (`00-goal-and-intent.md` promises 10-11). Verified directly today: `pyproject.toml:7` now reads `0.3.0`, and `examples/*.html` now carry a 2026-09-12 mtime — so this specific contradiction was quietly resolved between Sep-2 and Sep-12, but is nowhere recorded as a fix in the docs I read (no changelog entry found), which is itself a small instance of the "context evolves, not appends" rule not being followed for wins, only for failures.

## 5. Top 10 critical risks — "I finish the plan and still have half-broken architecture"

1. **Two drawing engines, one gated.** The block-drill graph engine (`graph.py`, `graph_engine.py`) is checked by Sable; the entry column and the tower/loop/modality views are raw SVG (`renderers/html/views.py`, 1,475 raw-SVG lines) with **no wiring or coverage gate at all** — the most-viewed page in the product can be silently wrong forever. Evidence: `z-docs/11-execution/FULL-AUDIT-2026-09-13.md:57-66` (F-3), `§7` "raw-SVG views with no gate at all (loop, tower, modalities)".

2. **No independent oracle; the reviewer keeps re-falsifying its own prior verdict.** Every check reads the parser's own AST (`09-judgment.md §3`, root cause 2); the Sep-13 self-audit itself required a second, independent audit to catch ~9 of its own wrong claims (`FINAL-PLAN-2026-09-14.md §1-2`). If "done" is repeatedly declared and repeatedly un-declared by the same class of reviewer checking itself, there is no evidence the *next* declaration of done will hold either.

3. **The deletion law is measurably failing.** Production code grew 11× in 3.5 months (14,031→154,263 lines) with deletion never exceeding ~0.2 of additions in any month (`FULL-AUDIT-2026-09-13.md §2`), against doctrine's own explicit stop-signal (`finish-line-and-scaling.md:78-80`). New files kept appearing after that audit (`git status`, untracked: `dit_cutover.py`, `dit_projection.py`, `absence.py`, `cross_surface.py`, `instance_cells.py`, `instance_closure.py`, `instance_dataflow.py`, etc.) — growth continued, not reversed.

4. **Governance has no human check between plan-rewrites.** Soumil delegated "ownership" of coherence to a Claude reviewer (`16-owner-intent…md` opening line); that reviewer writes the audits, the rulings, and its own grade (`09-judgment.md`: self-issued C+). The 23-question interview (`16-owner-intent…md`) is the last clearly-verbatim, human-anchored intent checkpoint (2026-09-02); every re-plan since (Sep-13/14 Unit 0-4, the Sep-21-27 repair fragmentation) is reviewer-authored with Soumil approving deltas in batches, not re-deriving the plan.

5. **The "second witness" (subprocess/meta-device execution) mechanism made the product worse before it made it better, and only covers one family.** SDXL: 3 s → 222 s / 24 MB page after cutover, requiring rescue unit S8.1, which still misses its own latency target as of 2026-09-09 (`21-drawing-ceiling…md §7`). Only SDXL has cut over as of `d922afb0` (2026-09-12); every other diffusion family still uses the old static path. Scaling this mechanism to the rest of the support set risks reproducing the same latency blowout family by family.

6. **A "lawful temporary bridge" has outlived its own stated deadline.** `DIT_CUTOVER_ENABLED` / `force_static_diffusion` plus 4,722 lines of static diffusion authority were declared "lawful until S10-2, which must land with S9-B" (`FULL-AUDIT-2026-09-13.md:67-68`); S9-B/S10-2 has since fragmented into four "repairs" (Sep 21-27) without landing — the doctrine's own anti-permanent-bridge rule (`project-doctrine.md:104-109`) is being tested by the calendar, not enforced by a check.

7. **A flagship model used as Soumil's own "beautiful" reference has had at least two distinct wrong canonical numbers across two audit cycles.** DeepSeek-V3's MLA output width was wrong on the shipped `17c`-era page, wrong again (a different value) in `opgraph._mla_region` on 2026-09-13 (F-5), on a model Soumil named as one of the renders he "truly consider[s] beautiful" (`16-owner-intent…md` answer b5). If the flagship demo model keeps re-breaking, less-scrutinized models are unlikely to be more reliable.

8. **The coverage denominator that defines "finished" is still not fixed to one number.** Five inconsistent target catalogues exist (117+48 / 118 / 299 / 198 / 15 rows), none referenced from current z-docs (`00-goal-and-intent.md §5`); the gated corpus (29 witnesses) is roughly a tenth of the broadest catalogue (299, "The Big Grill"). `finish-line-and-scaling.md`'s "measurable denominator" requirement has never been satisfied with an actual chosen list, so any declared "coverage exit" (S9-F) can be true against one catalogue and false against another.

9. **Scope inflation inside a unit meant to shrink scope.** Unit 2 was defined narrowly ("S9-B close, bounded to §D rows," `FINAL-PLAN-2026-09-14.md §4`); by 2026-09-27 it has produced four sequential "repairs," each with named sub-phases (rank-escape, rank-interval, rank-transfer, proof-closure, live-rank, R2-I1, R3-I1), and 15+ days of uncommitted work across ~80 modified production files and dozens of untracked receipt directories (`git status`, verified live; `11-execution/` directory listing, verified live). This is the Sep-2 judgment's root cause 4 ("process without release... 254 commits, no release... nobody can reproduce the receipts," `09-judgment.md §3.4`) recurring in a worse form: this time nothing is even committed.

10. **The project's own continuity mechanism has become unreadable, which is itself the "mechanism became the product" symptom.** `READ_AFTER_COMPACTION.md` — the file every future agent is required to read first, by explicit law ("Everything durable goes in z-docs… a compaction at any safe checkpoint loses nothing the next reader needs," `NEW_AGENT_BRIEF.md` law 9) — has degraded into dense, run-together, acronym-heavy shorthand ("Unsealedprod53f65e07…", "O12", "B26-B32", "rank-escape/rank-interval/rank-transfer") that is barely parseable by a human on first read (verified: read directly, `READ_AFTER_COMPACTION.md:1-60`). A project whose central artifact for "what is true and what is next" reads like this has optimized the review apparatus for internal self-continuity over intelligibility to the person it is supposed to serve — the precise failure the question asks about.
