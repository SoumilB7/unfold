## 2. The alternative approach (execution, not parsing)
1. Parts list = checkpoint headers: safetensors headers by HTTP range read; legacy .bin via a restricted unpickler that can only rebuild tensor metadata (allow-list: _rebuild_tensor(_v2), _rebuild_parameter, _rebuild_from_type_v2 wrapping only those, OrderedDict, torch.Size, *Storage names; legacy non-zip format supported). Nothing is executed, no weights downloaded.
2. Husk: the library's own class built with zero-storage weights (big tensors = zero-stride views; ≥3-D = one shared zero matrix expanded; no initialisers; in-place writes to zero views ignored; transformers.initialization functions no-op'd).
3. Real forward on CPU with real inputs from the repo's own processor, recorded by DagRecorder (TorchDispatchMode): every op, each input edge (op / param / buffer / model input / module constant / external), owning module, scalar constants.
4. Zero-skip: heavy ops (mm, addmm, bmm, baddbmm, linear, matmul, embedding, convolution, _grouped_mm) with a zero weight or an all-zero activation return exact zeros (or the bias) without arithmetic; zeros propagate. Proven identical op sequence, weights used and logits with vs without skip on Qwen3-0.6B/8B, Gemma-2-2B/9B, Qwen3-30B-A3B.
5. Score against the parts list with the library's own loader rules (transformers.conversion_mapping.get_model_conversion_mapping + core_model_loading.rename_source_key; `_keys_to_ignore_on_load_unexpected`).
Cost: DeepSeek-V3 671B 10.9 s / 0.66 GB; Llama-3.1-405B 10.8 s / 0.53 GB (was 13 min); 800B DeepSeek-V4-Pro 1.6 GB; warm 0.2–2 s/model; metadata ~7 MB/model.
No-weights guard (harness_v2/noweights.py): any weight-file download raises; snapshot_download gets weight ignore-patterns so tokenizer/config still load. Across 2,242 results: 0 weight files downloaded, max temp cache 37.7 MB/model.

DeepSeek-V3 walkthrough (evidence/deepseek-walkthrough/): 671,026,404,352 params; MLA q_a 7168→1536 → RMSNorm(1536) → q_b 24576; kv_a 7168→576 = 512+64 → RMSNorm(512) → kv_b 32768; o 16384→7168; interleaved RoPE on 64 dims, rotary key shared by 128 heads; score scale 0.1352337788608801; router fp32 sigmoid + correction bias (selection only) → 8 groups top-2 sum → top-4 groups → top-8 → normalise → ×2.5; 3 dense + 58 MoE; checkpoint layer 61 = MTP 13,463,426,304 params (no transformers code). Old tool on same model: dense FFN missing (−1,189,085,184), no MTP.
Config safety: any wrong/partial config field that changes a shape is caught against headers (DeepSeek wrong expert width/count/dense count/q_rank; Qwen3 dropped intermediate_size/num_kv_heads).

## 6. How to reach 100% without parsing code — built 2026-09-29 (worker_v2.py / inputs.py / gguf_parts.py)
Gap types: (a) ships but no available code runs it; (b) our inputs never reached its path; (c) the file cannot tell us.
A. More modes, run only while shipped weights are still unused (values/inputs change, recorded structure never does). Each optional model call is capped at 150 s, and no optional call starts once the job passes its budget (runner timeout − 400 s; the runner timeout is now 1800 s for transformers models, 2400 s for diffusion). A slow extra mode can never cost the main result.
   - mode:output_flags — every forward bool return_*/output_* set True, plus global_attention_mask when accepted. LED-base PARTIAL→FULL.
   - mode:long_input — input longer than 2× the largest window/compress/chunk/block/global/local/sliding value in any (sub)config (default 512, cap 4096); decoder gets 64 tokens. DeepSeek-V4-Flash: KV compressor now runs (40 weights), only MTP (library-declared-unbuilt) remains.
   - mode:router_random — router = weights feeding topk/argmax/sort in the recording. With zero weights every token is identical, so a random router alone does nothing (measured). The fix: router weights random ×0.02; 1-D scales of the next weighted op upstream (the norm before the router) set to 1±0.02; seeded noise added to the OUTPUT of every module holding the token-embedding table (tied copies included: in transformers 5, encoder.embed_tokens is a separate module sharing shared.weight); the long input is used. Tiny Switch: 80/80 experts run (T2 passes).
   - entry methods — public methods defined on the model's own classes (transformers.models.*), found by reflection, arguments filled by name from inputs that already ran (tokens→input_ids, images→pixel_values), mutating verbs blocked. ESM2 predict_contacts runs the contact head; only the library-declared-unbuilt position table remains.
   - image+text — tokenizer ids merged into image-only processor output when forward reads input_ids and the config has no image placeholder id. AltCLIP, TVP FAIL→PARTIAL.
   - wrapper roots without forward (Qwen2.5/3-Omni): passes built per direct sub-model from ITS signature and ITS sub-config; the pass loop calls that sub-model. Qwen3-Omni-30B FAIL→FULL.
   - CUDA-only kernel switches: on a CPU machine, config bools use_*kernel(s) are set False (the library's own pure-PyTorch path, like attn_implementation="eager"; recorded as implementation_switches). Zamba-7B FAIL→FULL.
   - zero-preserving in-place ops on zero-storage weights (mul_/div_ by finite non-zero, clamp_ spanning 0, zero_, …) are recorded and skipped: the result is provably still zero and the storage is shared. RWKV-4 (rescales weights with div_ at inference) FAIL→FULL.
   - forward requires bool_masked_pos → built per patch in the main pass (VideoMAE pre-training FAIL→PARTIAL; left: transformers drops q_bias/v_bias).
   - test text tokenizes to <4 tokens (script outside the tokenizer's alphabet) → ids from the tokenizer's own vocabulary (mms-tts-div FAIL→PARTIAL; left: VITS posterior encoder, training-only and training unsupported by the library).
   - processor fill-by-name — every processor argument filled by name (images; *mask* → white L image; other *image* → second image; text as "a cat." and ["cat","dog"]); the candidate that covers every required forward input wins (previously the first candidate with pixels). OmDet-Turbo FAIL→FULL, SegGPT FAIL→PARTIAL (remaining 1,024 weights chosen by string arg embedding_type — not guessed).
B. shipped_not_executed inventory in every result: groups {pattern, reason: library_declared_unbuilt | not_in_library_class | built_but_not_executed_in_any_mode, tensors, numel, shape} + modes tried. This is the parts list for drawing them as "shipped, not executed by the library", wiring unknown. FULL stays strict.

## 6A. Drawing what was graded: capture bundle → unfold renderer (2026-10-08)
One execution, one truth: the diagram is drawn from the run harness v2 graded, never from a second run.
- `worker_v2.py` with `BENCH_EMIT_CAPTURE=<dir>` (run_batch `--emit-captures DIR`) writes `<repo>.capture.json.gz`
  (`capture.py`): the op graph of the first main pass and of the pass with the most inputs, each pass's layer stacks,
  every square operand added to the scores (mask values, per operand), string op arguments (e.g. gelu approximate), a
  cache-on run of the drawn pass (after the result is saved, time-limited, fresh model) with every stored K/V tensor's
  producer, parameter shapes and tie groups, non-persistent buffers (e.g. inv_freq), the executed class, the config
  after the worker's switches, and the verdict. No weight values. Emission never changes a graded result (64 rows off vs
  on: identical except a temp-dir name; 2 rows first differed only because the Mac slept, see §7).
- `exec_to_ir.py <repo> <out.html> --bundle <path>` (or `--captures DIR`) builds unfold's ModelIR from the bundle and
  renders with the frozen renderer copy (`model-benchmark/renderer_snapshot`). That copy carries one IR change (not in
  git, listed in its SNAPSHOT_PATCHES.md): the fact status `execution_observed` and an EXECUTION EVIDENCE section that
  shows the scorecard (graded verdict and checks, hidden-path op accounting, every drawn fact as observed / declared with
  its evidence and its agreement with the config). Bundles are format /2; older ones are refused. Non-FULL verdicts are drawn with a visible
  warning; FULL_LEFTOVERS with a note.
- It draws only what it can show truthfully and otherwise writes `<out>.not_drawn.json` with the evidence. The core
  gate is op accounting: every op on the hidden-state path (forward closure of the token embedding) must belong to a
  drawn block, matched exactly (a norm is statistic → scaling → at most one weight and one bias, in order; RoPE is
  exactly x·cos + rot(x)·sin with rot from halves of the same x; before softmax only scalar scales and the one captured
  mask add; residual adds combine two hidden values). Plus: layers identical in ops, constants, weights, masks and
  rotation tables; no routing ops; one layer stack in every graded pass; causal mask captured; RoPE table geometric
  from 1 (llama3 scaling allowed, noted); no declared sliding window longer than the run; QK-norm before RoPE.
- Cross-examined in six rounds by an independent agent (74 probe models built from library default configs + 59 real
  bundles): every probe that would have drawn a false fact is refused with a true reason. In scope today: pre-norm
  sequential dense decoders (Llama 2/3, Mistral without window, Qwen2/3, OLMo-1, Granite, Helium, SeedOss, SmolLM3,
  StarCoder2, Ernie 4.5 …). MoE, sliding window, multi-tower, encoders, post/parallel norms, fused QKV, partial /
  complex / interleaved RoPE are refused with their reason (each is a next coverage item).
