Methodology caveat (read before treating 'uncovered' as 'does not exist on the Hub'): coverage found in the popularity pool is exact (a real repo's `config.model_type` matched). The FALLBACK path for model_types not in that pool does a Hub text search on the model_type string and keeps only the top-15 search results whose live `config.model_type` matches exactly -- it does not do a full corpus scan. Manual spot-checks found real, legitimate repos for several 'uncovered' entries that simply did not rank in the top 15 search hits for their name (e.g. `swin` -- `microsoft/swin-base-patch4-window7-224` exists and is used as a mechanism witness elsewhere in this report, but ranks below 15 in a generic 'swin' search now dominated by `swinv2`/`mask2former-swin-*`/timm results). ## Harness input path status

### implemented
- **text**: worker_zs.py step_text / worker_text.py text_inputs -- zeros input_ids via tokenizer-free zero tensor
- **image**: worker_zs.py step_image / worker_text.py step_vlm_image -- AutoProcessor + a real PIL image
- **audio**: worker_zs.py step_audio -- AutoProcessor + a real zeroed waveform
- **pipeline-prompt**: worker_diffusion.py run_pipeline -- the diffusers pipeline's own __call__ with a real text prompt (+ image/mask when the pipeline signature takes them)
- **image+mask**: worker_diffusion.py run_pipeline -- passes image + mask_image when the pipeline __call__ signature declares them (inpainting pipelines)

### NOT yet implemented
- **video**: no worker builds a real video tensor / frame-sampling input; AutoProcessor video path unexercised (vision_language.video_llm)
- **encoder_only_no_lm_head**: worker_zs/worker_text call the model as a causal LM (use_cache=False generation-style forward); bert-family/embeddings/reranker heads are not causal LMs, not implemented (encoder_only, all subcategories)
- **plain_vision_no_chat_template**: worker_zs.step_image / worker_text.step_vlm_image build a VLM chat-template (image+text) input via AutoProcessor; plain image classification/backbone/depth processors (ViTImageProcessor etc.) do not accept the paired text arg the workers pass, so a run would silently fail every step rather than measure anything real (vision_backbone, dense_vision_other)
- **detection_segmentation**: no worker builds the image+annotation/query input these heads expect, and there is no checkpoint-header ground truth scoring path for box/mask outputs
- **time_series**: no worker builds a numeric context-window tensor for forecasting models
- **speculative_decoding_draft**: EAGLE/Medusa-style draft heads need the TARGET model's hidden states as an extra input, not just input_ids; no worker builds that, and several draft repos ship non-standard config.json besides
- **speech_synthesis_output_scoring**: TTS/audio-LM/codec workers would need an audio-output ground truth path, not just weight coverage
