# Project doctrine

## The purpose

Model-unfolder reconstructs a model's architecture from artifacts the model
actually ships. It is not allowed to fill evidence gaps with a familiar family
template and present the result as fact.

## The central law

> Replace every act of architectural authority with an act of traceable
> evidence.

This law applies at three levels:

1. A model claim must trace to the checkpoint configuration, modeling source,
   or a derivation from already evidenced facts.
2. The parser must retain how strongly the claim is known, including ambiguity,
   missing source, and incomplete inspection.
3. A change is complete only when counterexamples, projection obligations,
   preservation evidence, and visual inspection support the claim.

## The one-way evidence law

Architectural truth moves in one direction:

```text
source/address
  -> exact component ownership and reachability
  -> mechanism interpretation
  -> typed fact
  -> canonical semantic structure
  -> HTML / cards / JSON / parameters / conformance
  -> projection receipt and audit
```

No downstream result may decide upstream truth. In particular, the absence of a
drawn node is not evidence that a parser consumption was inapplicable. A
consumption for an inactive or nonexistent owner is repaired at its producer;
it is not excused by the renderer.

## The producer-first correction law

When a check exposes a defect, presume the finding is real and locate the
earliest incorrect author. Do not make the check green by narrowing it around
the current output, turning a known error into an advisory, adding a broad
ignore, or registering indefinite debt. If the correct producer fix lies
outside the current change, stop and report that dependency.

## The required separations

### Config value versus code meaning

Configuration supplies the value selected by a checkpoint. Source code proves
what that field controls and how it enters computation. Neither replaces the
other. A field spelling or its mere presence cannot prove a mechanism.

### Observation versus interpretation versus presentation

- Observation records syntax and configuration occurrences.
- Binding attaches those observations to an exact component owner.
- Interpretation produces typed architectural facts.
- Normalization constructs shared semantic structure.
- Presentation decides which truthful facts enter a particular view.

A helper that performs several of these jobs is temporary coupling, not a
pattern to copy.

### Identity as address versus identity as fact

A model type, class name, or repository ID may locate source and provide a
display name. It may not select architectural structure. This boundary is
represented in code by typed identity roles and identity/taint guards.

### Unknown versus false

Unknown, ambiguous, source-missing, and proven-false are different states.
Unknown is a successful honest result. It must never become zero, `False`,
SiLU, causal attention, MHA, RoPE, or another conventional structure merely to
keep rendering simple.

## Priority order

1. Honesty and provenance.
2. Correct ownership and mechanism semantics.
3. Consistency across every projection.
4. Preservation of already-correct models.
5. Completeness.
6. Visual polish.

Beauty is valuable, but a beautiful unsupported claim is a product failure.

## The bounded-product law

The product is not a universal interpreter for arbitrary Python. Completion is
measured against an explicit set of supported upstream versions and mechanism
classes. A genuinely new mechanism may remain opaque with an actionable
explanation. This honest boundary is what allows the product to finish.

New checkpoints using supported mechanisms should require no code. New source
syntax should require one shared acquisition improvement. Only a genuinely new
mechanism should require a new interpreter and projection.

## The deletion law

A replacement path is not complete while the superseded config, identity,
default, compatibility, or renderer-authority path remains active. Every
mechanism change must name what it deletes or why a narrowly bounded temporary
bridge still exists.
