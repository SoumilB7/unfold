# Current product direction

## Governing destination

Model Unfolder is a source-grounded architecture explainer, not a universal
Python interpreter and not a family-template catalog.

The product contract is:

> Accurately explain the common mechanisms in a declared support set, preserve
> exact checkpoint values, disclose provenance and uncertainty, and render
> genuinely unresolved mechanisms as unresolved.

## Current engineering strategy

1. Enforce one-way evidence and producer-first correction.
2. Finish the actual-consumer receipt path and remove its coarse predecessor.
3. Consolidate repeated source readers into one owner-bound program index.
4. Convert mechanisms used by the support corpus end to end through all
   consumers.
5. Delete semantic config, identity, default, and compatibility authority as
   each mechanism cuts over.
6. Release at a measured support boundary with honest partial output for the
   long tail.

## Sources of implementation detail

Detailed files under `unfold-pkg/docs/` may contain useful counterexamples,
inventories, or worklists. They are not live status and their numbered phases,
old test counts, and completion labels are not product terminology. Before use,
revalidate each named path against the current code and restate the work as an
achieved mechanism outcome with a deletion boundary.

The active Z docs are the authority for:

- product scope and finish line;
- evidence direction and config/code division;
- producer-first failure handling;
- current implementation state;
- finite delivery outcomes.

## Non-goals

- perfect interpretation of arbitrary remote Python;
- zero config usage;
- a diagram for every repository at any cost;
- matching a familiar architecture when evidence is missing;
- keeping every historical check, ledger, or compatibility API permanently.
