# Finite delivery path

The remaining work is organized by achieved product outcomes rather than an old
execution sequence. This path is deliberately finite and deletion-oriented.

## Outcome 1 — close the fact-to-output proof chain

1. Finish and verify typed receipts from actual projection consumers.
2. Decide applicability from source-bound ownership and reachability.
3. Keep missing receipts blocking for mechanisms whose consumers declare receipt
   coverage.
4. Reject facts for inactive/nonexistent owners and receipts without facts.
5. Convert cards, JSON, parameters, and conformance to the same receipt model.
6. Delete the coarse manual projection-witness sets after parity.

Achieved result: every established fact reaches each promised output, and every
visible structural claim points back to evidence.

## Outcome 2 — consolidate source acquisition and ownership

1. Build one raw program index for classes, methods, construction, calls,
   branches, assignments, state, and source spans.
2. Bind exact component instances and recursive namespaces once.
3. Give readers typed missing-source, unsupported-syntax, ambiguous-owner, and
   incomplete-graph outcomes.
4. Convert existing scanners to the shared index and delete the superseded
   extraction paths.

Achieved result: new source syntax is fixed once and recursive components cannot
cross ownership boundaries.

## Outcome 3 — convert the supported mechanism surface

Prioritize mechanisms used by the declared support corpus:

- attention geometry, storage, masks, positions, and scaling;
- FFN activation, gating, storage, experts, and routing;
- norm/residual topology and heterogeneous layer schedules;
- recursive text, vision, audio, projector, and fusion components;
- diffusion streams and conditioning;
- diffusion transformer cells, UNet stages, VAE/codec cells, and scheduler
  update behavior.

Each mechanism change spans acquisition, fact, semantic representation, all
consumers, receipts, counterexamples, and deletion of the prior authority path.
The reported model is only a witness.

Achieved result: equivalent code receives the same explanation regardless of
model name or containing tower.

## Outcome 4 — remove temporary authority and release

1. Delete generic config-to-chip authors and semantic family tables.
2. Delete conventional fallbacks that strengthen unknown evidence.
3. Delete temporary fact, extras, and projection compatibility routes.
4. Restrict remaining YAML to syntax, address, schema, display, and verification
   vocabulary that cannot author structure.
5. Publish supported upstream versions, mechanism coverage, honest-partial
   behavior, and the representative release corpus.
6. Run unchanged-tree mechanical, preservation, conformance, and visual checks.

Achieved result: the long-running conversion ends. Future work is limited to new
upstream syntax or genuinely new mechanisms, not checkpoint-by-checkpoint fixes.

## Stop conditions

Pause a change immediately if it:

- makes a check green by weakening the check instead of fixing the producer;
- lets renderer output determine upstream applicability;
- adds a model-specific production branch;
- adds a compatibility route without a removal condition;
- grows a semantic table instead of binding source behavior;
- changes expected artifacts without explaining the evidence delta.

## Release boundary

Release does not wait for every Hub repository. It waits for:

- zero known confidently wrong claims in the declared support corpus;
- honest unresolved behavior for unsupported mechanisms;
- no family/model identity selecting structure;
- shared known mechanisms requiring no checkpoint-specific code;
- a stable proof chain across promised consumers;
- a shrinking or deleted temporary-authority inventory.
